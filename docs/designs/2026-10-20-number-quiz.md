# Изучение чисел

Отдельный раздел «🔢 Числа», независимый от словаря и алфавита. Встроенный каталог числительных 0–99 в женском роде, написание без огласовок и латинская транскрипция.

## Сценарии

1. Карточки 0–99 с четырьмя ответами: иврит → число, транскрипция → число, число → иврит с транскрипцией, число → иврит.
2. Название → ввод числа сообщением (0–99), выбор вопроса на иврите или транскрипцией. Некорректный ввод не засчитывается и оставляет вопрос активным.
3. Число → название для 0–10 включительно, шесть различных названий на иврите без транскрипции. Пользователь уточнил, что предпочитает инлайн и больше четырёх вариантов; выбрано шесть, чтобы не показывать все 11 на каждом вопросе.

Общие действия: пропуск, остановка, результат и список ошибок. После ответа показываются число, иврит и транскрипция. Ошибки и новые числа повышают вес, недавние вопросы не повторяются. Постоянный прогресс хранится по пользователю, режиму и числу; текущая сессия — в conversation_states.

## Архитектура

Domain: статический каталог, enum режимов, NumberProgress. Application: подбор вопросов через IRandomSource, форматирование через BidiText, проверка ввода, use case записи ответа через IClock и порт репозитория. Infrastructure: number_progress, Fluent API и сгенерированная EF-миграция. Worker: меню, callback, показ вопросов и обработка текстовых ответов. Telegram-типы остаются в Worker.

Рассмотрены альтернативы: CSV-тема не покрывает текстовый ввод и отдельную статистику; переписывание общего движка увеличивает риск для существующих квизов. Выбран самостоятельный раздел с переиспользованием имеющихся примитивов.

## Безопасность

Новых HTTP-эндпоинтов, секретов и внешних интеграций нет. Ответы проверяются относительно текущей FSM пользователя и сообщения, callback содержит короткий токен и индекс, устаревшие ответы отклоняются. Ввод ограничивается целыми 0–99, числовые переполнения отклоняются. Двойное нажатие гасит токен перед записью ответа. Ответы и содержимое сообщений не добавляются в логи. Все строки с ивритом обрабатываются BidiText.

## Проверка

NUnit с ручными fake-репозиториями: каталог и границы 0/10/11/19/20/99, направления, четыре/шесть уникальных вариантов, правильный ответ, отсутствие повтора, ошибочный ввод, запись прогресса, устаревшие callback, остановка и пропуск. Release build/test и проверка модели EF относительно миграций.
